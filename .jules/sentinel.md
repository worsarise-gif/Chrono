## 2024-05-11 - Information Leakage and User Enumeration in Auth Endpoints
**Vulnerability:** The authentication endpoints (`/api/auth/reset-password`, `/api/auth/send-otp`, `/api/auth/verify-otp`) were exposing internal error details (e.g. Firebase or SMTP stack traces) by returning `error?.message` in 500 responses. Furthermore, the `reset-password` endpoint did not prevent user enumeration, as an `auth/user-not-found` exception would propagate as a 500 instead of a simulated success response.
**Learning:** Returning `error.message` directly from catch blocks is dangerous, especially in external facing auth routes, as it exposes the underlying architecture and potential vulnerabilities to attackers. Likewise, distinct responses for existing vs. non-existing emails allow attackers to map out registered user bases.
**Prevention:** Always return a generic error message (e.g. `'An error occurred'`) on 500s from auth routes. For password resets and OTP generations, catch `auth/user-not-found` and return a generic success message that matches the expected output for a successful request.
