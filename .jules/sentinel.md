## 2024-05-27 - Information Leakage and User Enumeration in Auth Endpoints
**Vulnerability:** The authentication endpoints (`/api/auth/reset-password`, `/api/auth/send-otp`, `/api/auth/verify-otp`) were exposing internal error messages (`error?.message`) directly to the client in `500 Internal Server Error` responses. Additionally, `/api/auth/send-otp` allowed for user enumeration by returning a distinct `400` error if the email was already registered and verified.
**Learning:** Returning unhandled or framework-specific error messages directly to the client can expose sensitive details about the backend architecture, database schema, or third-party service integrations (like Firebase or Nodemailer errors). Allowing user enumeration enables attackers to compile lists of valid users, which can be used for targeted phishing or credential stuffing attacks.
**Prevention:** Always return generic error messages for unhandled exceptions in API routes (e.g., "An error occurred"). To prevent user enumeration, design authentication and recovery endpoints to return identical generic success responses regardless of whether the user exists in the system or not.
