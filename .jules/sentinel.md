## 2024-05-24 - User Enumeration and Information Leakage in Auth Endpoints
**Vulnerability:** The password reset endpoint leaked user existence by throwing an error on `auth/user-not-found`. Multiple auth endpoints (reset-password, send-otp, verify-otp) were passing raw `error?.message` directly into 500 error responses, potentially leaking sensitive stack traces, internal errors, or details about backend infrastructure.
**Learning:** Auth endpoints must return generic success/failure messages regardless of user existence to prevent enumeration attacks. Raw error messages from dependencies or the database should never be piped directly to client responses.
**Prevention:** Catch `auth/user-not-found` specifically and return identical successful-looking responses for both existing and non-existing accounts in credential recovery flows. Ensure all top-level catch blocks in API routes return a generic hardcoded error string rather than relying on `error?.message` for user-facing output.
