## 2023-10-27 - Information Leakage in API Fallback & Auth Errors
**Vulnerability:** The `/api/auth/reset-password/route.ts` API leaked user enumeration information by allowing an attacker to determine if a user exists based on whether the endpoint returned an error or successfully sent the email. Other auth endpoints (`send-otp`, `verify-otp`) leaked internal error details (`error?.message`) directly to the client in their 500 error responses, which could expose internal stack traces or system state.
**Learning:** Auth endpoints that attempt to perform operations on specific users, like resetting passwords or sending OTPs, must be careful not to reveal the existence or non-existence of a user by varying their response behavior. The codebase also contained a pattern of passing internal error strings to the client for 500 status codes.
**Prevention:** Catch user-not-found errors on auth endpoints and return the generic success response to prevent enumeration attacks. Also, always use generic error messages for 500 server errors on the client side, rather than forwarding potentially sensitive inner error properties.
