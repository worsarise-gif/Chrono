## 2026-09-11 - Prevent User Enumeration and Information Leakage in Auth Routes
**Vulnerability:** The authentication API routes (`/api/auth/reset-password`, `/api/auth/send-otp`, `/api/auth/verify-otp`) were leaking information about user existence by returning specific error messages (e.g., catching `auth/user-not-found` without returning a generic success or throwing a 400 for already verified users). Additionally, internal error messages (`error?.message`) were being passed directly to the client in 500 responses.
**Learning:** Returning specific errors for non-existent or verified users allows attackers to enumerate existing accounts. Passing raw error messages to the client can expose internal system details or stack traces, violating the principle of failing securely.
**Prevention:** Always return generic success messages for password resets and OTP generation regardless of whether the user exists. Never pass internal error messages directly to the client in HTTP responses; use generic error strings instead.
